১. পরিচিতি

FreeZone BD একটি বাংলাভাষী সোশ্যাল অ্যাপ। কোনো বিল্ড টুল লাগে না: সব ফাইল একটি ফোল্ডারে রেখে HTTPS হোস্টে আপলোড করলেই চলে। ছবি imgbb-তে যায় এবং ডেটাবেসে শুধু লিংক থাকে। ভিডিও ও ভয়েস মেসেজের জন্য ঐচ্ছিকভাবে Firebase Storage যোগ করা যায়।

ইউজার অ্যাপ (এই গাইড)

ফোল্ডারের সব ফাইল। শুরু হয় login.html ও feed.html থেকে।

অ্যাডমিন সাইট

admin-site/ ফোল্ডার, আলাদা হোস্টে রাখতে হয়। সেটআপ admin-site/README.md-এ আছে।

Firebase

দুই সাইটই একই প্রজেক্ট ও একই ডেটাবেস ব্যবহার করে।

মনে রাখুন: সব ফাইল feed.html-এর ফোল্ডারেই (একই স্তরে) থাকবে। সাব-ফোল্ডার নেই। শুধু admin-site আলাদা সাইট।

২. দ্রুত শুরু

  1. Firebase-এ প্রজেক্ট খুলুন, Email/Password সাইন-ইন চালু করুন, একটি Realtime Database বানান।
  2. config.js বানিয়ে auth ও db এক্সপোর্ট করুন (নিচে দেখুন)।
  3. database.rules.json-এর লেখা Realtime Database > Rules-এ পেস্ট করে Publish করুন।
  4. imgbb.js-এ নিজের কী বসান, app-info.js-এ নিজের তথ্য বসান।
  5. সব ফাইল HTTPS হোস্টে আপলোড করুন, Firebase-এ Authorised domain যোগ করুন।
  6. login.html খুলে অ্যাকাউন্ট খুলুন। নিজের uid admins/{uid} = true বসিয়ে অ্যাডমিন বানান।

৩. সেটআপ (ধাপে ধাপে)

৩.১ config.js

এই ফাইল আপনার নিজের; সব মডিউল ./config.js থেকে auth ও db নেয়।

import { initializeApp } from "https://www.gstatic.com/firebasejs/12.2.1/firebase-app.js";
import { getAuth } from "https://www.gstatic.com/firebasejs/12.2.1/firebase-auth.js";
import { getDatabase } from "https://www.gstatic.com/firebasejs/12.2.1/firebase-database.js";

const app = initializeApp({ /* Firebase Console > Project settings > Web app config */ });
export const auth = getAuth(app);
export const db = getDatabase(app);

// ভিডিও/ভয়েস আপলোড চালু করতে (পরে) নিচের দুই লাইন যোগ করুন:
// import { getStorage } from "https://www.gstatic.com/firebasejs/12.2.1/firebase-storage.js";
// export const storage = getStorage(app);
Firebase SDK ভার্সন: সব ফাইলে 12.2.1 ব্যবহার হয়। ভার্সন বদলালে সব ফাইলে একসাথে বদলাতে হবে।

৩.২ Rules Publish করা

Realtime Database > Rules > database.rules.json-এর পুরো লেখা পেস্ট করে Publish। এই ফাইল বদলালে প্রতিবার আবার Publish করতে হবে।

না করলে: নতুন ফিচারে "permission denied" আসবে। যেমন ইউজারনেম যাচাই, Boost, কল, ঘোষণার ব্যানার।

৩.৩ imgbb.js ও app-info.js

  • imgbb.js: IMGBB_API_KEY-এ আপনার কী। কী ব্রাউজারে খোলা থাকে (দেখুন নিরাপত্তা)।
  • app-info.js: অ্যাপের নাম, ভার্সন, MIN_AGE (১৮), পরিচালকের নাম ও ঠিকানা, সাপোর্ট ইমেইল, আইনি পেজের তারিখ (LEGAL_UPDATED)। এক জায়গায় বদলালে সব পেজে বদলায়।

৩.৪ হোস্টিং ও ডোমেইন

  • HTTPS লাগবে (Firebase Hosting, Netlify, GitHub Pages ইত্যাদি)। ক্যামেরা, মাইক ও কল শুধু HTTPS-এ (বা localhost-এ) চলে।
  • Authentication > Settings > Authorised domains-এ ডোমেইন যোগ না করলে লগইন হবে না।

৩.৫ অ্যাডমিন অ্যাকাউন্ট

Console-এ admins/{আপনার uid}-এ true বসান। মালিকের জন্য owner লিখুন (মালিককে প্যানেল থেকে সরানো যায় না)।

৩.৬ পুরনো ইউজারদের ইউজারনেম রেজিস্ট্রি (একবার)

ইউজারনেম এখন usernames/{নাম} = uid নোডে রাখা হয়, যাতে একই নাম কখনো দুজনে না পায়। যারা আগে থেকে আছে তাদের নাম ঢুকাতে: অ্যাডমিন প্যানেল > Users > Sync usernames now। একাধিকবার চালালে ক্ষতি নেই। ডুপ্লিকেট থাকলে তালিকা দেখায় (প্রথমজন নামটি রাখে)।

জরুরি: এটি না চালালে পুরনো ইউজারদের নাম নতুন কেউ নিতে পারবে।

৩.৭ Storage (ঐচ্ছিক, ভিডিওর জন্য)

  1. Firebase Storage চালু করুন, storage.rules-এ PUT_ADMIN_UID_HERE-এর জায়গায় অ্যাডমিনের uid বসিয়ে Publish করুন।
  2. config.js-এ storage এক্সপোর্ট করুন (৩.১ দেখুন)।
  3. এরপর ভিডিও ফিচারের "preview" নোটিশ চলে যায় এবং আসল আপলোড চলে।
ধরনসর্বোচ্চ আকারসর্বোচ্চ সময়Storage ফোল্ডার
পোস্টের ভিডিও৫০ MB৬০ সেকেন্ডposts/{uid}/
স্টোরির ভিডিও৩০ MB২০ সেকেন্ডstories/{uid}/

৪. অ্যাপের কাঠামো

অ্যাপ আসলে দুটি HTML পেজ: login.html (লগইন) ও feed.html (বাকি সবকিছু)। feed.js প্রতিটি "পেজ" দরকার মতো আলাদা মডিউল হিসেবে লোড করে (dynamic import), তাই শুরুর লোড হালকা থাকে।

জায়গাকী খোলেমডিউল

নিচের বার: Searchসার্চ পেজsearch.js

প্রতিটি পেজ mount(container, ctx) এক্সপোর্ট করে। ctx-এ থাকে db, currentUser, followingIds, postActions ইত্যাদি। কোনো পেজ নিজের টপ বার আঁকলে ctx.setHeader(false) দিয়ে শেয়ার্ড হেডার লুকায় (সার্চ পেজ তা-ই করে)। নতুন পেজ যোগ করতে feed.js-এর pageModules তালিকায় এক লাইন যোগ করুন এবং নিজের mount লিখুন।

৫. লগইন ও সাইন-আপ login.html · login.js

প্রতিটি ধাপ একটি পূর্ণ স্ক্রিন পেজ। স্লাইড অ্যানিমেশন, উপরে তীর বাটন ও প্রগ্রেস বার, নিচে বড় বাটন। ব্রাউজারের Back বাটনও ধাপে ধাপে পিছায়।

ধাপকী হয়
লগইনইমেইল, পাসওয়ার্ড, "Remember me", "Forgot password?"। নিচে "Create new account"।
রিসেটইমেইলে রিসেট লিংক। ইমেইল আছে কি না তা জানানো হয় না (প্রাইভেসি)।
১/৫ নামকমপক্ষে ২ অক্ষর।
২/৫ ইউজারনেমলিখতে লিখতে "available / taken" ও আইকন। নেওয়া থাকলে ফাঁকা নামের সাজেশন চিপ। নাম থেকে প্রথমেই সাজেশন আসে।
৩/৫ ইমেইলফরম্যাট যাচাই।
৪/৫ পাসওয়ার্ডকমপক্ষে ৬ অক্ষর, শক্তির বার।
৫/৫ নিশ্চিতসারাংশ কার্ড, ১৮+ ও শর্তে সম্মতির টিক, "Create account"।

ইউজারনেমের নিয়ম

  • ৩–২০ অক্ষর; শুধু ছোট হাতের a-z, সংখ্যা, _ ও .। শুরু বা শেষে ডট, বা পরপর দুই ডট চলবে না।
  • admin, support, freezone ইত্যাদি সংরক্ষিত নাম নেওয়া যায় না।
  • Abdul আর abdul একই ধরা হয় (সব ছোট হাতে সেভ)। ইউজারনেম পরে বদলানো যায় না।

অ্যাকাউন্ট খোলার ক্রম (গুরুত্বপূর্ণ)

  1. Auth-এ ইউজার তৈরি।
  2. usernames/{নাম} = uid লিখে নামটি দখল। রুল শুধু খালি নামেই লিখতে দেয়, তাই দুজন একসাথে চাইলেও একজনই পায়।
  3. users/{uid} প্রোফাইল লেখা।

দখল ব্যর্থ হলে বা প্রোফাইল না লেখা গেলে অ্যাকাউন্ট ও দখল করা নাম মুছে ফেলা হয়, আর ইউজারকে ইউজারনেম পেজে ফেরানো হয়। ইমেইল বা পাসওয়ার্ডের ভুলেও ওই ধাপে ফেরানো হয়।

লিংকে ধাপ: login.html?tab=signup সরাসরি সাইন-আপ খোলে। ?next=feed.html?post=ID লগইনের পর ওই পেজে নেয় (শুধু একই সাইটে)।

ফিচার-গেট

প্রতিটি ভিডিও-সংক্রান্ত ফিচারের তিনটি অবস্থা, অ্যাডমিনের Features পেজ থেকে বদলানো যায় এবং সঙ্গে সঙ্গে কার্যকর হয়:

মোডফল

১৭. Boost ও Sponsored boost.js · ads.js

ইউজার টাকা দিয়ে নিজের পোস্ট অন্যদের ফিডে "Sponsored" হিসেবে দেখাতে পারেন। অ্যাডমিন পেমেন্ট যাচাই করে অনুমোদন দেন।

প্যাকেজ

মেয়াদদাম
৩০ দিন৳ ৩০০
৬০ দিন৳ ৫০০
১২০ দিন৳ ১০০০

দাম database.rules.json-এও স্থির করা, কাজেই ব্রাউজারে বদলে লাভ নেই। দাম বদলাতে boost.js ও rules দুটোই বদলান।

ইউজারের ধাপ (পোস্টের ⋯ > Boost post)

  1. প্যাকেজ বাছাই।
  2. বাটনের নাম ও https লিংক (শুধু https চলে)।
  3. পেমেন্ট: bKash/Nagad নম্বরে Send Money, প্রেরকের নম্বর, TrxID ও স্ক্রিনশট। সব ঠিক থাকলেই "Complete" আসে। ৩ দিনের ফেরত নীতির বক্স দেখানো হয়।
  4. অর্ডার pending হয়ে অ্যাডমিনের কাছে যায়।

নিয়ম ও সুরক্ষা

  • শুধু নিজের পাবলিক পোস্ট Boost করা যায়। একই পোস্টে pending/active/refund_requested থাকলে নতুন অর্ডার হয় না। একসাথে সর্বোচ্চ ৩টি pending।
  • TrxID ডুপ্লিকেট রোধ: boostTrx/{method_TRXID} = uid আগে লেখা হয়; একই TrxID দুবার ব্যবহার করা যায় না।
  • "My boosts"-এ স্ট্যাটাস, ভিউ, ক্লিক ও "Request a refund"। এটি এখন Boost-এর নোটিফিকেশনে ট্যাপ করলে খোলে।

ফেরত (Refund)

অনুমোদনের পর ৩ দিন পর্যন্ত ফেরত চাওয়া যায়। অ্যাডমিন নিজে টাকা ফেরত পাঠিয়ে "Mark as refunded" দেন (অথবা কারণসহ "Keep running")। ৩ দিন পার হলে ফেরত নেই। নীতির লেখা terms.html ও privacy.html-এ আছে।

দেখানো (ads.js)

  • অনুমোদনের সময় অ্যাডমিন boostLive/{id} লেখে। ads.js সেটি পড়ে আসল পোস্ট posts/{postId} থেকে এনে দেখায়, তাই লেখা ও ছবি সবসময় হালনাগাদ।
  • জায়গা: ফিডে ৩য় পোস্টের পর, তারপর প্রতি ৫টিতে। প্রোফাইলে ২য় পোস্টের পর, তারপর প্রতি ৬টিতে।
  • কার্ডের ক্রম: লেখক ও "Sponsored" (✕ সহ) → লেখা ও ছবি/ভিডিও → লিংক বাটন বার (হোস্ট + বাটন) → লাইক, কমেন্ট, শেয়ার, সেভ। লেখা বা ছবিতে চাপলে পোস্ট খোলে।
  • আপনি যে পোস্ট Boost করেছেন তা নিজের প্রোফাইলে বিজ্ঞাপন হিসেবে আসে না। নিজের ভিউ ও ক্লিক গোনা হয় না।
  • বাদ পড়ে: মুছে ফেলা পোস্ট, followers/me অডিয়েন্সের পোস্ট, uid না মেলা, http লিংক, ব্লক করা লেখক, ফিডে ইতিমধ্যে থাকা পোস্ট।
  • দিনে সীমিত বার দেখানো; ✕ দিলে সেই ডিভাইসে লুকায়।
  • লিংকের rel="noopener noreferrer sponsored"।
  • কিছু ব্যর্থ হলে কিছুই ঢোকানো হয় না, ফিড আগের মতোই থাকে।

মেয়াদ শেষ

মেয়াদ ফুরালে অ্যাডমিন প্যানেলের "End and notify" দিয়ে বন্ধ ও ইউজারকে নোটিফিকেশন যায়। অ্যাডমিন চাইলে Re-open করে নতুন প্যাকেজ ও নতুন TrxID দিয়ে আবার চালু করতে পারেন।

অ্যাডমিনের সেটিং: bKash/Nagad নম্বর অ্যাডমিন প্যানেলের Boosts পেজে বসাতে হয় (config/boost)। না বসালে ইউজার পেমেন্টের নম্বর দেখতে পাবে না।

২৩. Rules ও ইনডেক্স

প্রধান নিয়মগুলো

  • usernames: যে কেউ একটি নির্দিষ্ট নাম পড়তে পারে (লগইন ছাড়াও, যাচাইয়ের জন্য), পুরো তালিকা নয়। লেখা যায় শুধু খালি নামে এবং নিজের uid দিয়ে; মুছতে পারে শুধু মালিক বা অ্যাডমিন। নামের ফরম্যাট ^[a-z0-9_.]{3,20}$।
  • users/{uid}/username: নতুন প্রোফাইলে usernames/{নাম} ঠিক তার uid-কে দেখাতে হবে; পরে বদলানো যায় না।
  • users/{uid}/name: ২–৪০ অক্ষর; বদলানো যায় ৬০ দিনে একবার।
  • posts: তৈরি করতে লাগে নিজের uid; সাসপেন্ড হলে পারে না।
  • boosts: মালিক ও অ্যাডমিন পড়ে। মালিক তালিকা পড়তে পারে শুধু orderByChild("uid").equalTo(নিজের uid) কোয়েরিতে। তৈরি হয় শুধু pending-এ, নিজের পোস্টে, নির্ধারিত দামে ও বৈধ TrxID-সহ। মালিক শুধু active থেকে refund_requested করতে পারে (৩ দিনের মধ্যে, অন্য কোনো ফিল্ড না বদলে)।
  • boostLive: সবাই পড়তে পারে; অ্যাডমিন লেখে; যে কেউ impressions/clicks শুধু +১ করতে পারে।
  • config/*: সবাই পড়ে, অ্যাডমিন লেখে।

২৫. ফিড অ্যালগরিদম feed-algorithm.js

প্রতিটি পোস্ট স্কোর পায়, সবচেয়ে বেশি স্কোর আগে দেখায়। স্কোরে সময় (নতুন বেশি), এনগেজমেন্ট (লাইক, কমেন্ট, শেয়ার), আপনার রুচি (interests.js), লেখকের সঙ্গে সম্পর্ক ও "দেখা" পোস্টের জরিমানা ইত্যাদি যোগ হয়। "Not interested" দেওয়া লেখক ও ট্যাগ কিছুদিনের জন্য নামে। বিজ্ঞাপনের জায়গা এই ফাইলের pickAdsForSlots বাছে। ফাইলের ওপরের মন্তব্যে প্রতিটি ওজন ও সেটিং বিস্তারিত আছে।

টেস্ট চালাতে: node feed-algorithm.test.mjs

  • পুরনো ইমেইলে সাইন-আপ চাইলে ইমেইল ধাপে ফিরে ভুল দেখায়।
  • লগইন, Remember me, Forgot password।

  • পোস্ট তৈরি (লেখা, ছবি ১–৪টি, পোল), লাইক, কমেন্ট, রিপ্লাই, শেয়ার, সেভ।
  • For you / Following; নতুন পোস্ট বাটন; পুল-টু-রিফ্রেশ; অফলাইন বার।
  • অডিয়েন্স (Public / Followers / Only me) অন্য অ্যাকাউন্টে যাচাই।
  • ব্লকের পর পোস্ট ও সার্চে আর আসে না।

সার্চ, বন্ধু, প্রোফাইল

  • সার্চ: Recent জমা, ✕ দিয়ে মোছা, Clear all; People/Posts/Photos/Polls ফিল্টার; Follow বাটন।
  • ডাবল বর্ডার নেই (লাইট ও ডার্ক দুই মোডে)।
  • প্রাইভেট অ্যাকাউন্টে ফলো রিকোয়েস্ট ও Confirm।
  • প্রোফাইল এডিট; নাম ৬০ দিনের সীমা।

চ্যাট ও নোটিফিকেশন

  • মেসেজ, ছবি, Seen, অনলাইন স্ট্যাটাস। কল (Wi-Fi ও মোবাইল ডেটায়)।
  • নোটিফিকেশন: গ্রুপ, Unread চিপ, Mark all as read, Remove, Confirm/Delete।

Boost (পুরো প্রবাহ)

  • ইউজার: Boost post → প্যাকেজ → বাটন ও লিংক → পেমেন্ট (ভুয়া ডেটা দিয়ে নয়, আসল ছোট লেনদেনে) → Complete।
  • অ্যাডমিন: Waiting-এ অর্ডার, Approve; নোটিফিকেশন যায়।
  • অন্য অ্যাকাউন্টের ফিডে ৩য় পোস্টের পর Sponsored কার্ড; লিংক বাটন বারের পরে লাইক/কমেন্ট/শেয়ার সারি; ক্লিক গোনা।
  • একই TrxID আবার দিলে আটকায়।
  • Refund: ইউজার অনুরোধ, অ্যাডমিন Mark as refunded; ৩ দিন পরে অনুরোধ বন্ধ।
  • মেয়াদ শেষে "End and notify"।

অ্যাডমিন সাইট

  • Sync usernames now; Posts পেজে ফিডের মতো কার্ড; Users সাসপেন্ড ও চালু।

২৭. সমস্যা ও সমাধান

"permission denied" আসছে

প্রায় সবসময় সর্বশেষ database.rules.json Publish করা হয়নি। Console > Realtime Database > Rules-এ পুরো ফাইল পেস্ট করে Publish করুন। সাইন-আপে এলে usernames নিয়মও Publish হয়েছে কি না দেখুন।

লগইন হচ্ছে না / "unauthorized-domain"

Authentication > Settings > Authorised domains-এ আপনার ডোমেইন যোগ করুন।

People সার্চে কেউ আসছে না

users-এর .indexOn-এ username, name, nameLower আছে কি না দেখুন (Rules Publish)। পুরনো ইউজারদের nameLower না থাকলে নাম দিয়ে নয়, username দিয়ে মিলবে।

সাইন-আপে "ইউজারনেম যাচাই করা যায়নি"

ইন্টারনেট বা Rules দেখুন। যাচাই না হলেও অ্যাকাউন্ট খোলার সময় রুল আবার চূড়ান্ত যাচাই করে, তাই ডুপ্লিকেট হওয়ার ভয় নেই।

পুরনো ইউজারনেম নতুন কেউ নিতে পারছে

অ্যাডমিন > Users > Sync usernames now চালান।

Boost করার সময় "My boosts" খালি / permission denied

boosts নিয়ম ও .indexOn: ["uid","status"] Publish করা আছে কি না দেখুন।

Sponsored কার্ড আসছে না

Boost অনুমোদিত (active) ও মেয়াদ বাকি কি না; পোস্ট পাবলিক কি না; লিংক https কি না; আপনি নিজেই লেখক নন তো; ✕ দিয়ে লুকিয়েছেন কি না দেখুন। কনসোলে boostLive পড়ার ত্রুটি আছে কি না দেখুন।

কল জুড়ছে না (শুধু মোবাইল ডেটায়)

call-config.js-এ TURN সার্ভার যোগ করুন। দুজনেরই অ্যাপ খোলা থাকতে হবে; HTTPS লাগবে।

ভিডিও আপলোডে "preview" নোটিশ

config.js-এ storage এক্সপোর্ট করা ও storage.rules Publish করা হয়নি।

ছবি আপলোড হচ্ছে না

imgbb.js-এর কী ঠিক আছে কি না, ও দিনের সীমা পার হয়েছে কি না দেখুন।

আইকন চৌকো/অক্ষর দেখাচ্ছে

Material Symbols ফন্ট লোড হয়নি (ইন্টারনেট বা ফন্ট ব্লক)। feed.html-এর ফন্ট লিংক ঠিক আছে কি না দেখুন।

ইনপুটে দুটি বর্ডার দেখা যাচ্ছে

ব্রাউজারের ফোকাস আউটলাইন ও ফর্ম-প্লাগইনের রিং একসাথে আসে। সার্চ ও লগইন পেজে তা ইনলাইন CSS-এ বন্ধ করা আছে। অন্য ইনপুটে হলে একই CSS (outline:0; box-shadow:none) দিন।

২৮. নিরাপত্তা

  • Firebase web config গোপন নয়; ডেটা বাঁচায় rules। তাই database.rules.json সবসময় Publish ও হালনাগাদ রাখুন।
  • imgbb কী ব্রাউজারে খোলা থাকে, যে কেউ দেখতে পারে। বদলে নেওয়া যায় এমন কী ব্যবহার করুন; অ্যাপ বড় হলে ছোট সার্ভার বা Cloud Function নিন।
  • এই ফাইলগুলোতে কখনো service-account কী বা অ্যাডমিন পাসওয়ার্ড রাখবেন না।
  • অ্যাডমিনের সংখ্যা কম রাখুন, শক্ত পাসওয়ার্ড দিন।
  • ইউজারের লেখা সবসময় escapeHtml() দিয়ে বসানো হয়; বাইরের লিংকে rel="noopener noreferrer" (বিজ্ঞাপনে sponsored) ও শুধু https।
  • পেমেন্টের স্ক্রিনশট ও TrxID শুধু মালিক ও অ্যাডমিন পড়তে পারে।

২৯. আপডেট দেওয়ার নিয়ম

  1. বদলানো ফাইলগুলো হোস্টে একই নামে প্রতিস্থাপন করুন।
  2. database.rules.json বদলালে আগে Rules Publish করুন, তারপর অ্যাপ।
  3. একসাথে বদলাতে হয় এমন জোড়া: login.html + login.js; ads.js + feed.js + profile.js (Sponsored কার্ডের অ্যাকশন সারি); boost.js + অ্যাডমিনের page-boosts.js + rules।
  4. ব্রাউজারে হার্ড রিফ্রেশ করুন (পুরনো ক্যাশ থাকতে পারে)।
  5. বড় বদলের পর টেস্ট চেকলিস্ট চালান।
  6. আইনি লেখা বদলালে app-info.js-এ LEGAL_UPDATED ও LEGAL_UPDATED_BN নতুন তারিখ দিন।
